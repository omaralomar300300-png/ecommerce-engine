# تقرير مشروع محرك المعالجة لنظام تجارة إلكترونية

## 1. فكرة المشروع

المشروع عبارة عن نظام Backend بسيط لمنظومة تجارة إلكترونية.  
الفكرة الأساسية هي إدارة المنتجات، المخزون، المحافظ المالية للمستخدمين، وطلبات الشراء.

عند إنشاء طلب شراء، يقوم النظام بالتحقق من الأمور التالية:

- وجود المنتج.
- توفر الكمية المطلوبة في المخزون.
- وجود محفظة للمستخدم.
- توفر رصيد كافٍ في المحفظة.
- خصم المبلغ من الرصيد.
- إنقاص كمية المنتج من المخزون.
- إنشاء الطلب وحفظه في قاعدة البيانات.

تم استخدام Spring Boot لبناء الـ APIs، وتم استخدام MySQL لحفظ البيانات بشكل دائم.

---

## 2. تقسيم المشروع

تم تقسيم المشروع إلى عدة أجزاء حتى يكون الكود واضحًا ومنظمًا.

### مجلد product

هذا الجزء مسؤول عن المنتجات والمخزون.

الملفات الأساسية:

- `Product.java`: يمثل جدول المنتجات في قاعدة البيانات.
- `ProductRepository.java`: مسؤول عن عمليات قاعدة البيانات الخاصة بالمنتجات.
- `ProductController.java`: يحتوي على روابط API الخاصة بالمنتجات.

أهم العمليات:

- إضافة منتج.
- عرض المنتجات.
- عرض منتج حسب الرقم.
- تعديل كمية المخزون.

---

### مجلد wallet

هذا الجزء مسؤول عن محفظة المستخدم ورصيده.

الملفات الأساسية:

- `Wallet.java`: يمثل جدول المحافظ.
- `WalletRepository.java`: مسؤول عن عمليات قاعدة البيانات الخاصة بالمحفظة.
- `WalletController.java`: يحتوي على روابط API الخاصة بالمحافظ.

أهم العمليات:

- إنشاء محفظة.
- عرض المحافظ.
- عرض محفظة حسب الرقم.

---

### مجلد order

هذا الجزء مسؤول عن طلبات الشراء.

الملفات الأساسية:

- `PurchaseOrder.java`: يمثل جدول طلبات الشراء.
- `OrderRepository.java`: مسؤول عن حفظ وقراءة الطلبات.
- `OrderController.java`: يستقبل طلبات الشراء من Postman.
- `OrderService.java`: يحتوي على منطق إنشاء الطلب.

تم وضع منطق الطلب داخل `OrderService` لأن عملية الشراء ليست عملية بسيطة، بل تحتوي على عدة خطوات مثل فحص الرصيد، فحص المخزون، خصم الرصيد، إنقاص المخزون، ثم حفظ الطلب.

---

### مجلد report

هذا الجزء مسؤول عن تقرير المبيعات.

تم إنشاء API يقوم بحساب عدد الطلبات وإجمالي المبيعات، مع معالجة الطلبات على دفعات صغيرة.

---

### مجلد load

هذا الجزء مسؤول عن معرفة نسخة السيرفر التي عالجت الطلب.  
تم استخدامه مع Nginx لإثبات توزيع الأحمال بين أكثر من نسخة من التطبيق.

---

### مجلد monitoring

هذا الجزء مسؤول عن مراقبة الأداء باستخدام AOP.  
يقوم بقياس زمن تنفيذ بعض الدوال وطباعة النتيجة في الـ Terminal.

---
